# Exact credentials, data and dependency checklist

## Required for the demonstrated local workflow

| Requirement | Why / obtain it | Secure configuration | Needed for tests? |
| --- | --- | --- | --- |
| Python bootstrap, uv, internet for first dependency download | Install Python/uv locally; `tools/dev.py setup` installs locked Python 3.12 packages | Local toolchain; no account secret | Yes, then checks run without cloud |
| CPU/RAM/disk | CPU training and local artifacts; allow several GB for Python/wheels and experiments | Keep platform home on a local disk | Yes |
| Local bearer identities | Authenticate API/CLI writes and separate human approval | Run `tools/create_identity.py`; keep tokens in a secret manager or untracked environment; server holds only SHA-256 map | Tests supply synthetic identities; no user secret needed |
| Synthetic imagery | Generated by the demo, already covered by reproducible code | `data/demo/incoming`; no external download or usage permission | Generated by tests/demo |

No AWS account, AWS credential, LLM API key, SageMaker role, real bucket or Evalora
token is needed for any local test or the complete demo. No secrets should be
pasted into chat. `.env.example` contains names and examples only.

## Required only for an optional real AWS demonstration

| Requirement | Why / where to obtain | Permissions / secure configuration |
| --- | --- | --- |
| AWS account and approved Region | Infrastructure/jobs/endpoint billing; choose in AWS Console | Explicit cost review and approval; default template Region is ap-south-1 |
| IAM Identity Center/SSO profile | Authenticate Terraform and human-operated boto3/CLI | `aws configure sso`, `aws sso login --profile NAME`; set AWS_PROFILE and AWS_DEFAULT_REGION; standard credential chain, no committed access keys |
| Deployment identity | Create narrowly named demo resources through reviewed Terraform plans | Project-scoped S3, EventBridge, Lambda, SQS, Logs, IAM role/policy, SageMaker package group/pipeline operations; IAM PassRole restricted to project roles and service conditions; read caller identity |
| SageMaker execution role | Read input/write execution state, pull the image and emit processing logs | Terraform output `sagemaker_execution_role_arn`; trust SageMaker, scoped S3 prefix, ECR repository, processing logs/job ARNs; IAM PassRole only to SageMaker |
| Lambda execution role | Start only the named pipeline and record logs/failures | Terraform-managed role: StartPipelineExecution on project pipeline, SendMessage on project DLQ, scoped log streams; X-Ray APIs require resource wildcard |
| ECR repository and reviewed image digests | Processing/inference custom containers | Build Docker worker/inference targets, scan/push to project ECR repository, pin @sha256 digest; human deployer needs ECR push/auth; execution role only pull/auth |
| Unique S3 bucket name | Input manifests, immutable artifacts and execution output | Terraform creates the bucket, encryption/TLS/public-access controls; externally supplied bucket adaptation is manual, not mandatory; keys remain under aerointel/ |
| SageMaker package/endpoint deployer permissions | Register pending packages, mirror authorized approval, create model/config/endpoint and monitor status | Create/DescribeModelPackage, UpdateModelPackage, Create/DescribeModel, Create/DescribeEndpointConfig, Create/Update/Describe/DeleteEndpoint on project ARNs; IAM PassRole only to the execution role |
| Runtime caller | Invoke a deliberately running endpoint | InvokeEndpoint only on the chosen project endpoint; use standard AWS credential chain |
| CloudWatch metric publisher and rollback alarms | Monitoring and native canary safety | PutMetricData restricted by namespace condition AeroIntel (AWS requires resource wildcard); DescribeAlarms and named alarm configuration/roles as reviewed by operator |
| Service quotas | Jobs and endpoint fleets require sufficient regional quota | Request quotas for selected ml.m5.large processing/hosting, including simultaneous old/new fleets during rollout |

The optional Terraform default does not create an endpoint or ECR repository.
Those are deliberate manual deployment prerequisites, not local blockers. Cloud
adapters are mutation-disabled by default and take explicitly injected SDK clients.
Tests use Moto/stubs with fake credentials and never your configured profile.

The application has no live LLM provider integration, so an LLM key is not required.
An external MCP host can optionally supply its own model/provider; configure that
host independently without giving the model unrestricted cloud credentials.
OpenTelemetry exporters/Evalora are optional host integrations; no exporter is
enabled and no telemetry credential is requested by the local platform.

## Required only for real aerial-imagery results

Provide a local directory of before/after RGB images, aligned binary masks,
verified dataset usage permission/reference and stable source-scene IDs. A small
LEVIR-CD+ subset is a candidate, not an already licensed asset in this repository.
Review its source terms yourself before downloading/incorporating it. Actual
spatial validation additionally requires reliable region identities, CRS and
footprints. If those are absent, keep fields null and expect REVIEW_REQUIRED and
blocked promotion under the locked policy. Do not invent coordinates.

No user action is needed to continue running the synthetic local workflow. User
decisions are needed only to select real-data permissions, approve a cloud budget,
provide SSO/role/resource choices securely, or select the public repository license.
